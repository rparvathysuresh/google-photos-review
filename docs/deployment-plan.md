# Railway Deployment Plan

This document outlines the step-by-step plan to deploy the Google Photos Discovery Engine to [Railway](https://railway.app). 

Since this project consists of a FastAPI backend and a Vite+React frontend, and relies on local file-based databases (SQLite and ChromaDB), we will deploy them as two separate services within a single Railway project.

## 1. Project Preparation

### Backend Adjustments
1. **Procfile/Start Command**: Ensure the backend can start properly in a production environment. We will configure Railway to run `uvicorn main:app --host 0.0.0.0 --port $PORT`.
2. **Path Resolution**: Ensure all paths (database, ChromaDB) are relative to a configurable `DATA_DIR` environment variable, defaulting to the current `data/` folder locally, but pointing to a mounted volume in production.
3. **CORS Configuration**: The backend `main.py` currently allows `http://localhost:5173`. We need to update the CORS origins to include the production frontend URL (once generated by Railway).

### Frontend Adjustments
1. **API URL Environment Variable**: The frontend currently hardcodes the API URL. We need to change this to use `import.meta.env.VITE_API_URL`, falling back to `http://127.0.0.1:8000/api` for local development.
2. **Static Server**: Since Vite generates static files, we will configure Railway to build the app (`npm run build`) and serve the `/dist` folder.

---

## 2. Railway Environment Setup

1. **Create Project**: Go to the Railway dashboard and create a new project from your GitHub repository (`rparvathysuresh/google-photos-review`).
2. **Monorepo Setup**: Railway will scan the repository. We will manually add two services from the same repo:
   - Service 1: **Backend** (Root Directory: `/`)
   - Service 2: **Frontend** (Root Directory: `/frontend`)

---

## 3. Backend Service Configuration (FastAPI)

1. **Root Directory**: Set to `/` (the root of the repository).
2. **Build Command**: Railway's Nixpacks will automatically detect Python via the root `requirements.txt`.
3. **Start Command**: `python run.py`
4. **Environment Variables**:
   - `GROQ_API_KEY`: Add your API key.
   - `PORT`: `8000` (Railway will automatically assign this).
   - `DATA_DIR`: `/app/data` (to point to the persistent volume).
5. **Persistent Volume**:
   - Go to the Backend service settings -> **Volumes**.
   - Add a new volume and mount it to `/app/data`.
   - *Crucial step to prevent ChromaDB and SQLite from wiping on every deploy!*

---

## 4. Frontend Service Configuration (Vite/React)

1. **Root Directory**: Set to `/frontend`.
2. **Build Command**: `npm install && npm run build`
3. **Start Command**: `npm i -g serve && serve -s dist -l $PORT` (Alternatively, Railway can detect it as a static site).
4. **Environment Variables**:
   - `VITE_API_URL`: Set this to the public URL generated by Railway for the Backend service (e.g., `https://backend-production-xyz.up.railway.app/api`).

---

## 5. Deployment Steps & Validation

1. **Deploy Backend First**: 
   - Wait for the backend to build and go live.
   - Generate a public domain for the backend in Railway settings.
   - Check the `/api/health` endpoint to ensure it's running.
2. **Deploy Frontend Second**:
   - Inject the newly generated backend domain into the frontend's `VITE_API_URL` environment variable.
   - Wait for the frontend to build and go live.
   - Generate a public domain for the frontend.
3. **Update Backend CORS**:
   - Add the frontend's public domain to the backend's `BACKEND_CORS_ORIGINS` environment variable so the API accepts requests from the live React app.
4. **Run Data Ingestion**:
   - Since the production database is empty (in the persistent volume), trigger the `/api/ingest/` endpoint or run a one-off task in Railway to seed the initial Reddit/App Store data into the production SQLite & ChromaDB.

---

## 6. Post-Deployment Checklist
- [ ] Backend is securely exposed and responding.
- [ ] Frontend successfully routes requests to the Backend URL.
- [ ] Persistent Volume is working (redeploying the backend doesn't wipe the vector DB).
- [ ] CORS is strictly set between the two services.
